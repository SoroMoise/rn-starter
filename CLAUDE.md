# CLAUDE.md

This file provides guidance to Claude Code when working with this repository.

## Project Overview

Monorepo boilerplate for a premium React Native / Expo app (pnpm workspaces + Turborepo):

- **`apps/mobile`** — Expo SDK 54 / React Native 0.81.5 / React 19: AdMob, RevenueCat, contextual paywall on a generic action counter, Firebase Analytics + Crashlytics, a local notification system ready to wire up, rating prompt, 20 languages, light/dark + RTL, onboarding (welcome → premium).
- **`apps/api`** — Cloudflare Worker (Hono): `/health`, `/example`, `/example/premium`, API-key auth, rate limiter, server-side RevenueCat check, FCM sender. Optional, with `packages/shared` (its types): `bash scripts/remove-api.sh` takes both out with the network layer kept only for them (Data Fetching).
- **`apps/web`** — Next.js 16 static site, English at the root and French under `/fr`: home, privacy policy, terms — the pages the app's legal links open.

Identity placeholders: name `RN Starter`, slug `rn-starter`, bundle id `com.yourcompany.rnstarter`, scheme `rnstarter`.

**`scripts/setup.sh` sweeps the identity everywhere it is written, and must stay exhaustive**: `app.config.js`, `constants/rating.ts`, the MMKV instance id, `apps/mobile/package.json`, the twenty translation files, `google-services.json.example`, `apps/web/lib/site.ts`, `apps/api/wrangler.toml`, the root `package.json`; it also writes the site and support address into `constants/legal.ts` (Legal links) and starts `.last_release_commit` at the current commit. Anything new that hardcodes the name, slug, bundle id, site or support address joins the sweep in the same change — a sweep that stops at the config ships an app calling itself "RN Starter" in twenty languages, with a Worker that replaces the template's.

## Living Documentation

`CLAUDE.md` (this file) and `apps/mobile/PROJECT_CONTEXT.md` must stay in sync with the code: whenever a change alters something either documents — routes, provider tree, stores, services, hooks, storage keys, premium gates, i18n policy, conventions — **update both as part of the same change, without being asked**, touching only the sections affected.

**The two split the work, and nothing lives in both.** `PROJECT_CONTEXT.md` says what exists — routes, providers, stores, services, hooks, storage keys, and the known gaps a reader must not "fix"; this file says why, and what not to do. A convention lives here only. Both stay in English: a context file rewritten in another language with conventions of its own becomes a second CLAUDE.md that neither keeps in step.

`apps/mobile/ADS.md` is the same contract for advertising — every placement's unit, cadence, gates and invariants; a change to any ad surface, unit or frequency updates it in the same commit. `docs/boilerplate-audit/ROADMAP.md` §4 lists the decisions already taken: read it before re-opening one.

## Commands

From the repo root: `pnpm dev` (Turbo, all workspaces), `dev:mobile`, `dev:api`, `dev:web`, `build:web` (static export into `apps/web/out`), `android` / `ios` (`expo run:*`), `build`, `typecheck`, `lint`, `deploy:api` (wrangler). From `apps/mobile`: `pnpm preb` / `preb:android` / `preb:ios` (expo prebuild), `build:aab` (signed .aab), `build:install` (signed .apk on the connected device), `analyze` (the Android bundle by package, in `report.html` — Bundle size).

Native `ios/` and `android/` are NOT committed (Continuous Native Generation): `pnpm --filter mobile preb` generates them before a device run. **That stays a decision, not a default to revisit**: the rule that nothing is hand-edited under `android/` only holds while every prebuild regenerates the tree, and a committed one must be prebuilt `--clean` at every change (a plugin's mod re-run on an existing tree duplicates or leaves stale what it wrote), restored by the release workflow before it commits, and swept by `setup.sh` for the identity its files carry.

Local native modules live in `apps/mobile/modules/`, autolinked through `expo.autolinking.nativeModulesDir`; their sources are committed and their Gradle output (`modules/*/android/build`, `.cxx`) is gitignored, since the `android/` rule does not reach them.

## Build & Release

- **Nothing is hand-edited under `android/`** — prebuild rewrites it. What the native project needs is a config plugin in `apps/mobile/plugins/`.
- **`./gradlew clean` is never how a build starts over.** It also cleans React Native's modules under `node_modules/`, codegen output included, and the new architecture's CMake build then fails far from the cause. Start over with `pnpm --filter mobile preb:android --clean`.
- **Release signing is a plugin** (`withAndroidSigning`) reading `apps/mobile/keystore.properties` **at build time**, so credentials can arrive after prebuild. Without it the Expo template signs `release` with the debug keystore, which Play refuses; a release build with neither `keystore.properties` nor EAS credentials fails on purpose. `keystore.properties`, `release.keystore`, `.env` and the Firebase config files are gitignored.
- **`withGradleMemory`** raises the daemon to `-Xmx4096m -XX:MaxMetaspaceSize=1024m`: past the template's budget R8 dies quietly and `bundleRelease` fails on missing intermediates (grep the log for "out of JVM Metaspace"). **`withGradleBuildCache`** turns on `org.gradle.caching` for the native modules' CMake builds. Both are plugins because `android/gradle.properties` is regenerated at every prebuild.
- **`withCrashlyticsMapping` uploads the R8 mapping only when `CI=true`**: a local `bundleRelease` must not overwrite the live release's mapping, and a release without one reports every frame as `a.b.c(SourceFile:1)`. Force a local upload with `CI=true ./gradlew bundleRelease`. It is wrapped in `plugins.withId` because the Crashlytics plugin applies itself at the end of `app/build.gradle`.
- **`withAndroidFontFilter` strips every `@expo/vector-icons` font outside `KEEP_FONTS` and refuses a prebuild that would strip one the app imports** — left to the build, the omission shows only in a release, as empty squares. Import a family by its subpath (`@expo/vector-icons/Ionicons`): the index import puts all fifteen families (4 MB) in the bundle.
- **A declared permission is a promise on the store listing.** `android.blockedPermissions` (`app.config.js`) removes from the whole manifest merge what nothing uses (`SYSTEM_ALERT_WINDOW`, `READ_EXTERNAL_STORAGE`, `WRITE_EXTERNAL_STORAGE`, which the template and `expo-file-system` declare); the debug build keeps `SYSTEM_ALERT_WINDOW` for the dev menu. A blocked permission fails at runtime, never at build time, so a feature that needs one takes it off the list in the same change (a media picker needs `READ_EXTERNAL_STORAGE` up to Android 12). `POST_NOTIFICATIONS` and `RECEIVE_BOOT_COMPLETED` never go on it (Notifications).

### Continuous delivery (GitHub Actions)

`.github/workflows/release-android.yml` fires on `workflow_dispatch`, or on a PR **merged into `main` carrying the `release` label** — closing a PR, or merging without the label, releases nothing. `.github/scripts/compute-android-version.sh` derives the version from Conventional Commits since `.last_release_commit` (`feat` → minor, `!` / `BREAKING CHANGE` → major, else patch), from `const version` in `app.config.js` and that file's `versionCode` formula — **the two must stay in step**. The job versions, prebuilds `--clean`, signs, `bundleRelease`s, uploads to the **internal** track (3 attempts, `.github/actions/publish-play/`) and pushes `chore(release): vX.Y.Z [skip ci]` with `app.config.js` and `.last_release_commit` staged by name — the tree also holds the restored keystore and `.env`, and nothing of `android/` is staged back.

- **The PR title becomes the Play release name** (`<version> - <title>`, cut at 50 characters): lead with the subject and the action.
- The job **refuses** Google's sample AdMob app id, a `MOBILE_DOTENV` that forces a tier (Monetization) or sets a consent test aid (Monetization) and placeholder legal links (Legal links).
- The Play package id is **read from `app.config.js`**, never written into the workflow, or it keeps pointing at the template's listing after `setup.sh`.
- If all 3 publish attempts fail, read the **first** one and the job summary before re-running: an attempt can commit its Play edit and still report failure, the later ones die on `apkUpgradeVersionConflict`, and a re-run recomputes the same version. Recovery is a hand bump of `app.config.js` and `.last_release_commit` to what the Play Console holds.
- The bump is pushed with the workflow's `GITHUB_TOKEN`, which no ruleset or branch protection can exempt: on a `main` closed to direct pushes the build reaches Play and the bump is refused. The first build of a new app goes up by hand — the Play Developer API only publishes to an app that already holds one.
- The README's *Android release* section is the human half of this one (trigger, versioning, first release, secrets, recovery); a change to any of them updates both.
- Secrets: `MOBILE_DOTENV`, `GOOGLE_SERVICES_JSON`, `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`, `PLAY_SERVICE_ACCOUNT_JSON`. The AAB is kept as an artifact **only** when no publish attempt landed; `purge-artifacts.yml` clears the backlog on demand.
- `.github/workflows/ci-api.yml` lints, typechecks, dry-run builds and deploys the Worker on the `release-api` label (`CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`); `remove-api.sh` deletes it with `apps/api`.

## Architecture (mobile)

### Navigation

Expo Router: a root `Stack` whose first screen is the `(tabs)` group, the onboarding gated in `AppContent` before the tabs (inventory in `PROJECT_CONTEXT.md`).

- **A screen that covers the tabs is a stack route beside `(tabs)`, never a tab.** A file inside `(tabs)` becomes a tab scene under the bar with no stack to dismiss, and `router.push` to it switches tabs. `unstable_settings.initialRouteName` keeps `(tabs)` under a stack route opened from a deep link or a notification, so back lands on the tabs instead of leaving the app.
- **The onboarding moves by step name, never by index.** A step gated on the device joins `buildSteps()` from what its capability reports, which can arrive after the first frame — an index then points at a different step, and a funnel keyed by index files two steps under one name. `goToStep(kind)` / `goNext()` resolve neighbours by name, the progress bar reads `steps.length`, and the name travels with every onboarding event.
- **A step that asks the user something is built on `OnboardingStepLayout`**, its CTA inside the scroll view so the step stays usable at the largest font scale, and its `secondary` label and handler travelling together. The starter ships none; an app's first is listed in `buildSteps()`.
- **Whatever owns the screen without being a route takes the back key itself**: at the root of the tab stack a key left to the navigator exits the app. `OnboardingScreen` listens to `BackHandler` and steps back from every step but the first; its sheets and modals are native `Modal`s and answer the key first.
- **A route that answers the back key uses `useHardwareBack(onBack)`**, whose listener lives in a `useFocusEffect` so only the focused route hears the press. It needs a navigator above it; a non-route surface listens to `BackHandler` itself.
- **A flow that ends resets the stack; it never `replace`s its way home.** `router.replace('/')` swaps the top entry only and leaves the flow's earlier screens under Home. Use `resetToHome(href?)` (`utils/navigation.ts`); a route that finds its session gone returns `<ExitToHome />`, never `<Redirect href="/" />`, which is a `replace`.
- **The onboarding ends on the entitlement, never on a purchase call.** A `purchasePlan()` promise resolves before React commits the new tier, and a restore goes through no callback at all: an effect keyed on `isPremium` completes the flow on the premium step and shows `ProWelcomeModal` once on an earlier one.

### Provider Tree

Drawn in `PROJECT_CONTEXT.md`. Persisted Zustand stores hydrate synchronously from MMKV at module import, so there is no async gate and no forced rehydration at boot (Storage).

### State Management

Zustand v5, `persist` + MMKV via `mmkvStateStorage` (list in `PROJECT_CONTEXT.md`). The onboarding's current step is never persisted: each step writes its answer into the store it owns.

### Storage

- **MMKV is the only key-value store, and `@react-native-async-storage/async-storage` does not come back**: an async store puts the boot gate back for every screen. `persist` wraps what it writes in a `{ state, version }` envelope, so a value hand-written under a store's key silently rehydrates to the defaults; read a store from outside Zustand the way `getActiveLanguageFromStorage` (`i18n/service.ts`) does. (`@tanstack/query-async-storage-persister` is only named after AsyncStorage; it is handed the MMKV adapter.)
- **What a store's `merge` decides stays in memory until something writes it.** `persist` writes on `setState` only (a `migrate` excepted), so what `merge` resolves — a restored timer closed, a stale entry purged — is resolved again at every cold start, and the symptom lands one launch after its cause. A store whose `merge` changes what was on disk raises a module flag and forces one write once hydration is done:

  ```ts
  onRehydrateStorage: () => () => {
    if (!mergeResolvedSomething) return
    mergeResolvedSomething = false
    queueMicrotask(() => useStore.setState({}))
  },
  ```

  The microtask is not optional: MMKV hydrates synchronously inside `create()`, before `useStore` is assigned. Normalise transient state on the way out in `partialize` (`phase: phase === 'running' ? 'running' : 'idle'`) rather than persisting it as it is. Neither starter store needs the flush.
- **What grants something lives in its own encrypted instance, and only there** (`secure.ts`: the subscription cache, the ad-free window). It is obfuscation, not secrecy — the key ships in the bundle. MMKV reads the key's first 16 bytes, and the key never changes once released, or what it wrote becomes unreadable. A new entitlement key goes there; a preference does not. **Never encrypt the main instance**: every install's data would become unreadable. An app porting this onto a released build copies the plaintext values across once, at import, before any reader; the starter ships no migration.
- **No copy of that instance leaves the device.** `withBackupRules` excludes `mmkv/entitlements` and its `.crc` from cloud backup and device transfer (`dataExtractionRules`, and `fullBackupContent` for Android 11 and below) and keeps expo-modules-core's record of the permissions asked (Notifications): a copy that can be restored can be edited into Pro first. Everything else restores; an app whose `files/` holds a library a day-stale snapshot would resurrect takes more out, as its own decision. This closes the attack on the app's copy, not on RevenueCat's own cache.
- **The generic action counter is fed by `recordAction()` (`useActionRating`), never by `incrementAction()` alone**, which offers the moment to nothing. It is never reset: the paywall policy's cooldown and lifetime cap pace it, and a counter that could be rewound would make both meaningless.
- **A rewarded video watched while an ad-free window is open adds to what is left**, up to `AD_REWARDED_FREE_MAX_MINUTES`: overwriting took back minutes already earned.
- **A last-used setting is remembered per feature, never by default.** A choice people make the same way every time (an export format, a brush size) is kept in a storage domain of its own; one taken from what is in front of them (a crop, a tool) goes with the screen, or the next visit opens on a choice made for something else. A kept setting a tier gates is a preference, not an entitlement, and is clamped on every read (Monetization). The starter remembers the theme and the language, nothing else.

### API Layer

`apps/mobile/services/api/` holds the SDK wrappers and the pure policies (inventory in `PROJECT_CONTEXT.md`; rules in Monetization and App Rating). `backendClient` throws by name when `.env` lacks `BACKEND_URL` or `BACKEND_API_KEY`, rather than let a relative URL fail as an outage.

**Notifications** (`apps/mobile/services/notifications/`). The starter asks for nothing and schedules nothing; the app's first notification is the first caller.

- **The permission is asked by the feature that needs it, where the user sees what it buys** — never at launch, never from a scheduling path, which runs as the app is left. `POST_NOTIFICATIONS` stays declared: on Android 13+ a notification from an app that never asked is dropped with no error. A toggle that defaults to on cannot be what asks, since nobody flips it; a refusal writes the intention back to off. Past a permanent denial the request resolves at once with `canAskAgain: false`, and the honest route is `Linking.openSettings()`.
- **Whether to ask is the OS's answer, never a flag the app kept.** The main instance rides backup and transfer, so a stored "already asked" reaches a phone where nothing was asked. expo-modules-core's own record (`shared_prefs/expo.modules.permissions.asked.xml`) would make an asked-but-denied permission read `canAskAgain: false` on a new phone, so `withBackupRules` keeps that file on the device.
- **The scheduler never asks, and never fails quietly.** `syncDailyReminders` cancels its group then schedules one trigger per entry, queued so the latest call holds; without the grant it resolves `'permission_missing'`, and a native failure or a time out of range (checked before anything is cancelled, since expo rejects one trigger at a time) resolves `'failed'` with a non-fatal — never a rejection, since its callers are effects. The syncing effect depends on the grant as well as on the list, or a grant given back in the settings leaves the reminders gone; title and body are frozen at scheduling, so a language change syncs again. Reminders fire within Android's inexact window: Play grants `USE_EXACT_ALARM` to alarm, timer and calendar apps only. expo-notifications re-arms them after a reboot through its own `RECEIVE_BOOT_COMPLETED`, so `blockedPermissions` never names it, nor `POST_NOTIFICATIONS`.
- **A channel's sound is frozen when it is created, and the app offers no toggle for it**: Android applies only a new name and description to an existing channel, and one re-created under the same id comes back with its old settings. A channel that must sound differently takes a new id — `defaultChannel` in `app.config.js` follows, the old one is deleted and its triggers are scheduled again (a trigger whose channel is gone lands in "Miscellaneous"). The foreground handler always asks for the sound: on Android `shouldPlaySound: false` also drops the heads-up banner.
- **Remote push is not wired on the device, and `@react-native-firebase/messaging` is not installed**: a background handler nothing registers would look like working push. Adding it means the package, a handler registered at the JS entry point (never a lazy route module) and a token registered with the backend.
- **`expo-notifications` carries a patch that must survive every bump** (`patches/expo-notifications@0.32.17.patch`, a try/catch around `NotificationForwarderActivity.onCreate`: some OEM ROMs hand the intent back without its extras and the app crashed on a notification tap). `pnpm.patchedDependencies` pins the exact version so a bump fails loudly; re-cut the patch against the new source.
- **`expo-notifications` always writes the `aps-environment` entitlement**, whatever `mode` says: it is declared in `app.config.js` so the config states what the build produces, and the App ID needs the Push Notifications capability or the iOS release fails code signing.

**Promo coordination** (`apps/mobile/services/promo/`).

- **`promoCoordinator` is the single authority over interruptive surfaces** (`PromoSurface`): no stacking (`isSurfaceVisible`) and **one automatic interruption per session, all types included** (`canPresentAutoPromo` / `markAutoPromoShown`), so an ad and a promo never land in the same session. A paywall the user opens, and the consent form, register their visibility but spend no budget. Adding a surface is a `PromoSurface` member and its setter; `canPresentAutoPromo` reads `isSurfaceVisible` rather than re-listing them.
- **A failure the user just met mutes the automatic promos.** `sessionSignals` holds one friction for `FRICTION_TTL_MS` (ten minutes), not overwritten while live, and the contextual paywall and the rating ask refuse as `friction` — a pitch minutes after a failed payment is the bad rating this prevents. Mark a purchase or restore that failed for any reason but the user's own (a cancelled sheet, a pending payment) where the failure is shown; not a failed price load, boot sync or `configure`, which show nothing. **An app marks its own failures the same way** — a `FrictionReason` member and `markFriction(reason)` where the failure happens. There is no `resetSession()`: the process is the session.

### Data Fetching

TanStack Query v5 in `QueryProvider` (`PersistQueryClientProvider`, the MMKV persister, the app version as cache buster).

- **Nothing is persisted until you say so**: `PERSISTED_QUERY_KEYS` is empty until an app adds its key prefixes. It once whitelisted another app's key, which read as configured and persisted nothing.
- **Connectivity is the app's own, whatever the backend.** `useNetworkStatus` holds the one NetInfo subscription (`getIsOnline()` / `subscribeToNetworkStatus()` outside React) and reads NetInfo's unknown state as online, so nothing reads as offline on a connection that works. It feeds the query client's `onlineManager` (React Native has no browser `online` event: without it retries burn through offline and `refetchOnReconnect` never fires), the rating ask and `OfflineBanner`, and stays when the backend goes. A query retries three times at most and never a status that cannot succeed (`isNonRetryableError`, `utils/apiErrors.ts` — one list `withRetry` reads too). Connectivity never decides the entitlement (Monetization). A networked screen mounts `<OfflineBanner />` at its top, never a NetInfo read of its own, which would flash at launch on the unknown state.
- **An app with no backend runs `bash scripts/remove-api.sh`**: `apps/api`, `packages/shared`, `ci-api.yml`, the Worker's root scripts and turbo task, `QueryProvider`, the `@tanstack/*` packages, `axios`, `withRetry`, `utils/apiErrors.ts` and the `error.*` keys only they read, `backendClient` and `exampleService` go; `useNetworkStatus` and netinfo stay. It refuses a dirty working tree and leaves the docs to whoever runs it. **Anything added only for the backend joins its list in the same change**, as an identity joins `setup.sh`'s.
- **`withRetry` is for a call made outside a query**; a `queryFn` calls `getBackendClient()` directly, or each attempt would retry again. It gives up with an `ApiRequestError` whose `statusCode` and `code` a caller branches on — never its message, which is translated.

### Monetization

- **AdMob** — `apps/mobile/ADS.md` is the reference. Lazy-init, disabled when premium or ad-free. `AdService.setPremium` has one writer, `SubscriptionProvider`, so buying Pro mid-process drops a preloaded interstitial and its pending retry.
- **AdMob identifiers are literals, never `.env`, and a pending unit requests nothing.** App ids in `app.config.js` (Google's sample until the app has its own — the SDK crashes with none), unit ids and kill switches in `constants/admob.ts`: they ship in the bundle either way, and an incomplete env once shipped a release with empty ids — no ad, no error, no revenue. `pickUnitId` resolves a pending unit to `null`, read as "request nothing". Never lend a pending placement another one's unit: AdMob reports revenue by unit. `__DEV__` always resolves to `TestIds`.
- **An action is counted first, then offered to one promo, in a fixed order**: `recordAction()` increments the lifetime counter whatever follows, offers the moment to the contextual paywall, then to the interstitial (only an ad the user saw takes it), and a moment neither took arms the rating ask (App Rating). The first to take it ends the chain; all three draw on the session's single interruption. The paywall comes first because it earns — do not flip the order. `recordAction({ allowPromos: false })` counts a moment that must not be interrupted: the first success, an abandoned or failed action.
- **The interstitial settles when it closes, not when it is handed over.** The native `show()` resolves when the ad reaches the activity and Android never reports a failed presentation, so `showInterstitialAd()` resolves `true` on `CLOSED` and `false` on `ERROR`, a rejected `show()` or no `OPENED` within `PRESENTATION_TIMEOUT_MS` — a visibility flag left raised would freeze every automatic promo. A failed instance is replaced; an ad that opens late still pays its slot or reward on `onEnd`. Only a closed ad resets the cadence and spends the interruption. Consent is re-read at show time.
- **One predicate decides whether a placement runs.** `useAdPlacementActive({ unitId, enabled })` is what `AdBanner` renders from and what its screen reserves `AD_BANNER_RESERVED_HEIGHT` from; a screen that recomputes its own condition pads for a banner consent hid, or lets one cover its last row. The rewarded offer reads `useCanServeAd` (every gate but the ad-free window, which the section answers itself): no offer where no video can be served, none in front of a subscriber before the store answered.
- **A banner is mounted once per visit and unmounted when its screen blurs** (`useStageActive` in `AdBanner`): a `BannerAd` refreshing under the top of the stack, or rebuilt by an in-screen toggle, is impression inflation, and it costs the account.
- **Nothing requests an ad on a Firebase Test Lab device.** Play's pre-launch report taps ad views from devices with no test-device identity, and AdMob bills that as invalid traffic — an account suspension. `modules/app-environment` reads `firebase.test.lab` and `adsAllowedInEnvironment()` gates the banner, both ad services and the consent flow.
- **Nothing requests an ad before consent does.** `consentService` runs Google's UMP flow and is the **only** caller of `mobileAds().initialize()`: an ad served ahead of the form is the violation itself, on the AdMob account. The default is `canRequestAds: false`, read by every ad surface; the form is gathered at the frame the onboarding ends on — never earlier, never for a subscriber. Where `arePrivacyOptionsRequired`, Settings grows a row to reopen it; otherwise the row is absent. `UMP_DEBUG_GEOGRAPHY` / `UMP_TEST_DEVICE_IDS` (`.env`, read under `__DEV__` only) show the form from outside the EEA; the release workflow refuses a `MOBILE_DOTENV` that sets either.
- **RevenueCat** — `ENTITLEMENT_PREMIUM` (`constants/purchases.ts`) is hardcoded on purpose: not secret, and an incomplete env would silently ship a paywall that sells nothing. The SDK keys come from `.env`. `openPaywall({ source })` from `SubscriptionProvider`.
- **`FORCE_FREE` / `FORCE_PRO` override the tier for development, and write nothing**: read inside `applyCustomerInfo`, so every path follows them, and never reaching `subscriptionStorage`. `FORCE_FREE` wins when both are set. `FORCE_PRO` walks the Pro paths before the store holds a product — which is why the release workflow refuses a `MOBILE_DOTENV` that sets either: shipped, one locks subscribers out and the other gives Pro away.
- **`openPaywall` is the single choke point, and it refuses** — resolving `false`, nothing opened or tracked — for a subscriber and until the onboarding is complete, so `paywall_shown` only counts impressions that could convert. Surfaces still hide their own offer from a subscriber: a button the choke point refuses is a dead one. The contextual paywall records its impression only once `openPaywall` resolves `true`.
- **The offer is data, not code.** Product ids, prices, periods, trial length and plan count all come from `offerings.current` (`buildOfferingPlans` → `OfferingPlan[]`); every surface renders from `usePremium().plans` / `defaultPlan`, phrases it through `usePaywallPlans({ source, surface })` and buys through `purchasePlan({ plan, source, surface })`. Never reintroduce a hardcoded product id, a fixed monthly+annual pair or a literal trial length: three plans, a weekly plan, a one-time purchase or no trial must all render truthfully. Only `offerings.current` is read — another offering would misprice the screen and detach the purchase from the experiment measuring it.
- **The paywall is assembled from blocks any selling surface reuses** (`components/paywall/`) over `usePaywallPlans`; `PaywallTrustRow` only says what holds for the selected plan (a one-time purchase has nothing to cancel, only a free trial is free). The onboarding's premium step sells through the same hook and blocks.
- **A one-time purchase is offered when the subscription is turned down, never beside it.** Listed with the subscriptions, a lifetime price reads as the bargain and takes buyers who would have renewed for years; offered as the paywall closes, it only meets people who were about to pay nothing. `pickLifetimeOffer` takes the offering's one-time plan out of `usePaywallPlans().options`, and the paywall's first close (button or back key) raises `LifetimeOfferCard` instead of closing — once per opening, the second close closes. The plan stays listed when the offering's metadata sets `lifetimePlacement: 'inline'` (a RevenueCat experiment compares the two without a release), when the offering highlights it, or when nothing recurring is left to protect; the onboarding sells only the default plan and is untouched. The card states its charge (`legalNote`), offers no urgency (the price is the same at the next opening) and no break-even against years of a subscription, and its purchases carry `surface: 'lifetime_offer'`.
- **`PremiumGate` blurs what it locks, it does not erase it**: the silhouette of the user's own content is what sells, so a `BlurView` and a 0.55 veil. `experimentalBlurMethod="dimezisBlurView"` is required — without it Android draws no blur and the veil hands the content over in clear — and the blur samples the screen the gate sits in: inside a native `Modal` it would blur the screen under the modal.
- **Every button that buys states what it will charge, right beside it** (`usePaywallPlans().legalNote`: price, period, and for a trial its length and what it turns into): Play's subscriptions policy asks for them where the offer is made, and a surface without a plan card is where they go missing. The exit sheet's copy follows the default plan, never "7 days free" whatever the store sells.
- **Every step of the purchase funnel says where it came from**: `source` (what brought the sale up — a new spelling splits the funnel with no error) and `surface` (`PurchaseSurface`) ride on every `purchase_*` and `restore_*` event beside `product_id` and `offering_id`, and money carries its own `currency` (logged as USD, a ₹3,499 plan reads as $3,499). `paywallAnalytics` composes the paywall's events so a field cannot miss one; a surface that sells without `openPaywall` passes its own `PurchaseOrigin`.
- **The purchase's own answer is the answer**: a call that did not throw is not a granted purchase, and "Welcome to Pro!" over a free tier is the one lie the user cannot check. RevenueCat rejects an unsettled payment (`PAYMENT_PENDING_ERROR`, nothing shown), so a purchase that resolves without `ENTITLEMENT_PREMIUM` means the user paid for nothing — a product never attached, or a template id left in place: `purchase_failed` (`entitlement_inactive`) and a non-fatal naming the active entitlements.
- **Failures are classified by their code, and only the unknown is a non-fatal.** `purchaseService.reportFailure` sorts by code, never by message (translated, version-dependent); known reasons are breadcrumbs, since a condition counted as a crash buries the bugs. Every catch of the provider goes through it, and the toast follows the reason. Ad failures follow the same rule through `reportAdFailure`: a no-fill is the network's answer, a wrong unit id or a presentation that never opened is a non-fatal.
- **Nothing interruptive fires without an offer behind it, and an empty offer says so.** `useContextualPaywall` refuses before recording an impression while no plan has loaded — `isInitialized` is true even when `getOfferings()` failed, and a captive portal would spend a lifetime impression on nothing to buy. The selling surfaces replace plans and CTA with `paywall.offerUnavailable` and `PriceRetryNotice` (`retryPrices()`), never a disabled button over a missing price.
- **Entitlement and prices are two independent calls**, each with its own error boundary: a store that will not quote a price must not cost the subscriber their tier, as a single `try` around `Promise.all` did. Offerings refetch on foreground. A `configure` that throws ends the price loading; `retryPrices` / `refreshSubscription` start the store again rather than call an SDK never configured, a foreground does not.
- **A free trial is only a trial when `introPrice.price === 0`, and its length comes off the product** (`readFreeTrial` → `hasTrial` / `trialDays`): a paid intro price is an offer, and promising days the store does not grant is a false commercial claim. The badge, the CTA and the onboarding frieze render from those, the frieze not at all without a trial, and it promises only what happens on its own (unlock today, billing on the last day) — never a reminder nothing sends.
- **No social proof the store cannot back**: no rating and no user count on the paywall. An app with real store numbers adds its own, fed from them.
- **One list sells Pro, and it names only what the free tier cannot do.** `PRO_BENEFITS` (`constants/purchases.ts`) feeds `PaywallPerks` and Settings' Pro banner alike — three lists once drifted apart; each entry names a limit the free tier enforces, added in the change that adds its gate (the starter gates its ads, its one entry). A benefit that depends on the build is keyed off what delivers it (a native module present), never `Platform.OS`. A limit interpolated into copy goes in `params` as `limit`, never `count`, which i18next reserves for plurals.
- **A free-tier limit applies on read, never on write.** The store keeps everything the user chose and `useCappedByTier({ items, freeLimit })` returns what the tier allows, read by every screen, sync and scheduler — a limit enforced only on the add button keeps Pro-era items alive after the tier lapses, and truncating the store destroys what a renewal should hand back. The hook reads the cached tier and never waits on `isInitialized`, which gave a free user Pro's list for the first frames; a long list reads it per row against the same `limit`. A remembered setting that outlives its gate is clamped on every read. The starter caps nothing yet: the first limit is the hook's first caller, with its `PRO_BENEFITS` entry in the same change.
- **Contextual paywall** — fires at a value moment once the action count reaches `minActions`; the session count only holds it back during the first session (as an OR beside the action count it always fired first). The trigger names the source; none fires at launch — a cold start is not a value moment — nor while a friction is live. `rewarded_ad_dismissed` follows only a video closed before its reward, never one watched in full or one that failed to open.
- **The grace period after a failed payment belongs to the store, not to the app.** Play and Apple keep a lapsed subscription active through their window, so RevenueCat reports it active; a local window on top handed every cancelling subscriber a free week. `persistFromEntitlement` writes only what the store answered — "no active entitlement" clears the cache. The app adds one informational line, `BillingIssueBanner`, with no CTA.
- **Cancelling is reachable from the app**: `PremiumBanner` shows *Manage subscription* only when `purchaseService.managementUrl` is non-null — never a guess between Play and the App Store.
- **`subscriptionStorage.derive(now, gracePeriodMs)` is the offline allowance, not an extension**, read only through `unverifiedFlags()`: to seed the tier before the store answers, and in the `catch` of a `getCustomerInfo` that could not reach the store (`SubscriptionGraceBanner` then says the clock is running). Never on a path where the store answered. The failed request is the offline signal, never a connectivity flag: behind a captive portal the device reads as online.
- **`applyCustomerInfo` is the single place a CustomerInfo becomes the app's tier** — boot, foreground sync, purchase and restore — so they cannot disagree and none re-asks the network.

### App Rating

- **Play forbids pre-filtering the review.** No opinion question and no star picker before the card: a qualifying moment calls `requestNativeReview()` and Play's card is the whole ask. `AppRatingModal` compiles, mounted nowhere, beside `SENTIMENT_GATE_ENABLED` (off) that nothing reads: bringing it back means wiring it, not flipping the flag.
- **One pure policy decides, from a moment, and names every refusal.** `useRatingPrompt().maybeAskForRating({ moment })` hands the state to `evaluateReviewRequest` (`reviewPolicy.ts`), which asks or tracks `rating_ask_suppressed` with its `reason` — Play is silent, so that reason is the only answer to "why does the app never ask?". A `RatingMoment` is a point where the app just delivered something, never a step inside a task; only `STRONG_RATING_MOMENTS` may open the card. The ask spends the session's interruption (`promo_collision`) but registers no visibility: Play's card exposes none, so budget and attempt are spent before it is asked for. A live friction refuses as `friction`, a lost connection as `offline` — an attempt spent offline buys a 42-day cooldown for a card that cannot load.
- **An action arms the ask; the user's return raises it.** The instant an action completes is the worst moment to ask, so `recordAction()` only arms (`reviewStorage.setArmed`, persisted) and `RatingAskHost` raises `action_completed` at a launch or on a return after `RATING_ASK_MIN_AWAY_MS` away, `RATING_ASK_SETTLE_MS` after the screen is back — Android reports every activity over the app (ads, the billing sheet, Play's card) as a background, and the threshold is what makes it a return. The arming lasts until the ask launches or a refusal outlives the session (`refusalOutlivesSession`). The host mounts only once the session has started — an ask before `resetSession()` spends a budget the reset hands back — and an ask raised at a launch takes that session's interruption before any action, on purpose.
- **The two store paths are split and not interchangeable.** `requestNativeReview()` is for automatic flows only: Play enforces an undocumented quota, silently skips the dialog once spent and reports nothing, which is why Google forbids wiring it to a button. It waits `REVIEW_FLOW_SETTLE_MS` on a plain timer (`InteractionManager` is deprecated and never sees a Reanimated animation) and asks nothing once the app has left the foreground: on Android the library throws beyond any JS catch without a current activity. `openStoreListing({ reason })` serves every explicit tap and nothing automatic. An error in the review flow is neither shown nor allowed to change the app's flow; a device with no store card is refused up front as `review_unavailable`, before any budget is spent. Android derives the listing from the package id; the App Store needs `APP_STORE_APP_ID`, `null` until the iOS release.
- **No event can mean "the user rated."** `rating_ask_shown` means a moment qualified, `review_flow_launched` only that the API was called; `likely_displayed` is a dashboard heuristic, never a branch. The truth is the Play Console rating count.
- **Attempts are spaced, never spent once.** `reviewStorage.recordRequest` records an attempt, not a conclusion, so a call swallowed by the quota is retried later. `softResetDays` **must** stay above `cooldownDays × backoffMultiplier^(requestCap − 1)`: below it every re-ask lands past the reset and the cap never binds. `isOptedOut()` still reads the flags the old star gate wrote; nothing writes them now.

### Brand assets

**Every brand image is drawn from one mark by `scripts/generate-brand-assets.py`**: edit the script and re-run it (`pip install pillow`, a maintainer's tool), never hand-patch a PNG. Each output carries a constraint nothing reports until a store enforces it: the store icon full bleed and RGB (stores cut their own corners), the adaptive foreground over transparency at two thirds (the launcher shows the central 72 dp of 108), the splash over transparency (Android 12+ cuts it to a circle), the notification icon a pure white **silhouette** (every opaque pixel takes the system tint). The script's `BACKGROUND` is also `splash.backgroundColor` and `android.adaptiveIcon.backgroundColor` in `app.config.js`: they change together. The shipped mark is a placeholder.

### Legal links

**The legal links are constants, never environment variables**: `constants/legal.ts` builds `LEGAL_URLS` from `APP_WEBSITE_URL`, opened from Settings and beside every buy button, where both stores require them to work — an incomplete env once shipped links that open nothing. Until `setup.sh` writes the app's own, the release workflow refuses the placeholders. **The paths are a contract with every build installed**: `/privacy` and `/terms` are never renamed, translated or given a locale prefix, and a move to another domain edits the constant and `SITE.url` in `apps/web/lib/site.ts` in the same change.

### Safe area

**One surface owns the bottom inset, and on a tab it is the tab bar.** `PremiumTabBar` is absolute and pads itself by `max(insets.bottom, 8)`, so `ScreenContainer` runs `edges={['top', 'left', 'right']}` — padding the scene too counts the inset twice. The scene spans the window, so anything anchored to the bottom adds the inset itself through `useTabBarPadding()`. A stack route over the tabs has no tab bar: its bottom controls add `insets.bottom` themselves, never `useTabBarPadding()`, which would float them over nothing. Sheets are their own window and add no bottom padding; the content they are given owns `insets.bottom` — a fixed `pb-8` buries the last row under a three-button bar.

### Large screens

**A large screen gets a centred column, never a second one.** Android 16 ignores `screenOrientation` above 600 dp, so tablets, foldables and freeform windows run the app in landscape; the `orientation: 'portrait'` lock stays, since below 600 dp it holds. `ScreenContainer` caps its content at `UI_CONFIG.MAX_CONTENT_WIDTH` through `maxWidth` + `alignSelf` — never binding on a phone, no dimension read, no re-render on resize. What lives outside it caps itself (a native `Modal` is its own window). The anchored ad banner is handed the column's width: sized from the device it hangs past its container, where Android delivers no touch (`ADS.md`). Nothing inside the column is sized from `useWindowDimensions().width` (size against the container's `onLayout`), and `Dimensions.get()` is never read at module scope: captured at import, it never follows a resize. `useResponsiveLayout()` serves what a style cannot express: `isLargeScreen` gates an adjustment that must not reach a phone, `gutter` lets an overlay reach the window's edges.

**Resizing must never recreate the activity.** `withAndroidConfigChanges` adds `smallestScreenSize` to `MainActivity`'s `configChanges`, which the Expo template omits: a destroy-without-finish leaves React Native dismissing a `Modal`'s `Dialog` on a detached `DecorView`, which crashes the app whenever a sheet is open. The guard is missing upstream; the manifest is the only lever.

### Accessibility

- **Every control says what it is, what state it is in and what it does, and nothing else is a stop.** A pressable carries a role (`button`; `link` for what leaves for a page or a site; `radio` in a `radiogroup` for a choice of one; `switch`, `tab`, `adjustable`), a name (its text, or an i18n `accessibilityLabel` when it shows only an icon), its state (`checked`, `selected`, `disabled`, `busy`, `expanded`) and, for a slider or a running task, an `accessibilityValue`. A heading is a `ThemedText` in `display`, `title` or `sectionHeader`, which carry the `header` role; another variant used as a heading passes it. A decorative icon is hidden (`importantForAccessibility="no"`), or its row is one `accessible` element read as a sentence. A row that shows a value without acting is a `View`, never a pressable without a handler (read as a disabled button); a row that cannot act right now passes `disabled`. A sheet's or dialog's backdrop is not a control, and the first stop is its title.
- **Nothing acts on a timer by itself while a screen reader is on.** A countdown that ends in an action waits for the tap (`useScreenReaderEnabled()`), and a reader turned on mid-countdown stops it: a restart the user did not ask for drops TalkBack's focus mid-sentence. A message that leaves on its own stays as long as `AccessibilityInfo.getRecommendedTimeoutMillis` says.
- **Progress is announced politely, never at every tick.** A value that changes many times a second is never a live region. A running task is a `progressbar` announced at each quarter (`useProgressAnnouncement`); a count that moves once per item can be a polite live region; a task that ends is announced once.
- **No font-scale cap, ever.** `maxFontSizeMultiplier` and `allowFontScaling={false}` do not appear in the app: Android reaches 200 %, and the people who set it need it. A height set around text is a minimum (`GradientButton` reads a `height` in its `style` as one), a label wraps rather than being cut (`numberOfLines` only where an ellipsis loses nothing), text sharing a row with a control shrinks, a screen whose actions sit at the bottom scrolls, and the tab bar grows by its label's line (`tabBarHeight(fontScale)`). What only a phone can show is each app's pass before its first release (`PROJECT_CONTEXT.md`, Known gaps).

### Styling

NativeWind v4, dark mode `'class'`. `GradientButton` for primary CTAs. Reanimated 4 + Moti (what Moti costs: Bundle size).

- **A rem is 15 dp** (`inlineRem: 15` in `metro.config.js`). NativeWind's default is 14, which renders every Tailwind class at 7/8 of its CSS size with no error; 16 (a browser's rem) read as zoomed in on a device, a slight system font increase looking like the maximum. Don't drop the option to "use the default", and don't raise it back to 16 without checking on a device.
- **A style that can be a class is one, so the whole UI follows the rem.** `inlineRem` converts `rem` only: a `style` value stays at its fixed dp, and so does an arbitrary px class. A size on the Tailwind scale takes its named class (`leading-7`, `p-4`); one off it is an arbitrary rem (`w-[2.875rem]`, the px ÷ 16), never an arbitrary px; a text size stays `text-[Nrem]` where it overrides a `ThemedText` variant (two named sizes tie alphabetically) or must not take the named class's line height. Three kinds of value stay in px on purpose: a minimum height or width (`min-h-[44px]`), a floor read against the device rather than the type scale, so a touch target does not fall under what Android asks (a button built from padding alone takes the floor too), a border width, and anything JS positions from (a size a computation reads back). A `text-*` class carries its line height, so text sized from a fixed `fontSize` keeps the old one with `leading-[Nrem]`. What stays in `style` has a reason: Reanimated styles and runtime numbers (insets, measured sizes, a constant like `UI_CONFIG.MAX_CONTENT_WIDTH`, which a literal class would duplicate), props that are not styles (icon `size` / `color`, `LinearGradient colors`), components with no `className` (`LinearGradient`, `BlurView`, `GradientButton` with its `style` / `gradientStyle`: it reads `height` and `borderRadius` out of them, so a `className` on it is the change that would let its callers convert), custom shadows, `fontVariant` and `direction`. A wrapper from `createAnimatedComponent` takes a class as it is, since Reanimated renders the component NativeWind registered (`AnimatedPressable`, `components/ui/AnimatedPressable.tsx`); **never wrap one in `cssInterop`**, which folds the class and a `useAnimatedStyle` into one object that Reanimated reduces to its animated values — the paywall's plan cards lost their layout, border and background that way.
- **The theme setting stores an intention, never a scheme.** `DEFAULT_SETTINGS.theme` is `'auto'`, mapped to NativeWind's `'system'` by `applyColorScheme`; whatever needs the scheme on screen reads `useThemedColor()`, never `settings.theme`, which is not `'dark'` on a dark phone left on System.
- **Brand colours are roles, never hues.** `constants/palette.js` holds the `accent`, `pro` and `success` scales, read by `tailwind.config.js`, `UI_COLORS` and `Colors.ts`; a rebrand swaps the scales and every surface follows, and a hue written into a component (`bg-blue-500`, `'#8b5cf6'`) is the one place it misses. The file stays CommonJS because the Tailwind config `require`s it. Status colours keep Tailwind's names (amber warning, red error, orange offline), as do the gold stars.
- **Every tab shares one gutter and one heading line**: `paddingHorizontal: 20` on the `ScrollView`'s content container — never a margin on the scroll view, which narrows its track, nor per block — and `ScreenHeading` at `mt-3.5`, so nothing shifts between tabs.
- **A screen that forces the system bars hands them back.** A screen with chrome of its own mounts a second `AppSystemBars` with explicit styles; the status bar stacks its mounted props, the navigation bar does not (`setStyle` is one global value), so `AppSystemBars` stacks the forced navigation styles itself — the last mounted wins, the theme's comes back when none is left.
- **A font size raised from `style` takes its line height with it**: `ThemedText` derives one whenever `style` sets `fontSize` without one, unless a `leading-*` class does; a plain `Text` gets no help — set both.
- **Three more traps fail without an error:**
  - **A state variant (`active:`, `hover:`, `focus:`) goes on the `Pressable` itself, never on a `View` inside it.** NativeWind turns such a `View` into a `Pressable` of its own, which wins the responder negotiation: the real button's `onPress` never fires.
  - **A horizontal `ScrollView` inside a column takes `flexGrow: 0`**: React Native's default `flexGrow: 1` makes it stretch down and eat the column.
  - **A `BlurView` passes `experimentalBlurMethod="dimezisBlurView"`, and pays for it.** Without it Android draws no blur at all; with it, expo-blur re-blurs its nearest `Screen` whenever what lies under it redraws. `PremiumTabBar` pays that on purpose; if it shows in a trace, dropping the prop there is the first thing to try.
- **Gradients are tokens** (`GRADIENTS` in `constants/uiColors.ts`), named by role so a rebrand edits values and never names; `pro`, `rewarded` and `success` take their stops from `palette`, `cta` and the onboarding backgrounds are drawn by hand and a rebrand redraws them. The `satisfies Record<string, readonly [string, string, ...string[]]>` is what expo-linear-gradient requires, and turns a one-colour token into a build error.
- **Toasts go through `ToastProvider`**; a native modal sits above the app window, so mount `ModalToastViewport active={visible}` inside it to surface a toast over it.
- **`ModalBottomSheet` is assembly only**: `useSheetSnap` owns the springs, snap points and dismiss pan, and the sheet's scrollables' native gesture runs alongside that pan. A scrollable that is neither — a wheel, a carousel — reads the pan through `useModalSheetPanGesture()` and blocks it with `Gesture.Native().blocksExternalGesture(pan)`, or the sheet wins every flick. Content that drags on its own raises `dragLock` while it holds the finger, and a pan it held at any point springs the sheet back instead of dismissing: the lock stops the sheet moving, never the pan's translation from accumulating.
- **A dialog is `ModalDialog`**, its `footer` outside the body so the actions never scroll away. **The keyboard does not resize a native modal on Android** (`SOFT_INPUT_ADJUST_RESIZE` resizes nothing under edge-to-edge, and `useWindowDimensions` keeps reporting the whole screen), so `ModalDialog` pads its centring box by `useKeyboardHeight()`; a `KeyboardAvoidingView` inside a `Modal` does not cover this — do not swap it back in. Like the sheet, the dialog mounts its own `GestureHandlerRootView`: on Android a gesture inside a native modal is only recognised under a root view in that window.
- **A view that sets its own height from a measurement of its own content ignores a report within a pixel of the height it just set.** On a non-integer density Yoga's rounding returns the animated height as a pixel of noise, and re-arming the resize for that echo shivers for the whole visit. The starter has no such view yet; the first one carries the guard.
- **A settings row is `SettingsRow`, and the whole row is the touch target.** A switch row passes `toggle` and draws `AppSwitch`, a decoration with no handler, under `accessibilityRole="switch"` — an interactive `Switch` inside a pressable row is two targets that can disagree. A row with neither `onPress` nor `toggle` is information; one that cannot act right now passes `disabled`. `SettingsLinkRow` stays for a title and a chevron: a `link` by default, `role="button"` for one that opens something in the app.
- **A wheel is turned with a thumb, not a cursor.** `WheelPicker`'s touch column is much wider than its digits, its `unit` drawn inside with `pointerEvents="none"`: every pixel between two wheels scrolls one of them. Don't narrow the columns or leave a gap nothing scrolls. Inside a sheet the wheel blocks the pan.

### Bundle size

**The JS bundle is part of the Play download, and Metro does not tree-shake**: an import from a package's index brings the whole package. Run `pnpm --filter mobile analyze` before and after any dependency change and read the difference.

- **`date-fns` is imported per function** (`import { format } from 'date-fns/format'`), never from the index, which puts all ~200 functions (~250 KB) in the bundle; a type-only import costs nothing.
- **`@revenuecat/purchases-js-hybrid-mappings` resolves to an empty module on Android and iOS** (`metro.config.js`): react-native-purchases requires its ~740 KB browser implementation at import and runs it only without the native module. The stub is gated on `android` and `ios` by name, never on `platform !== 'web'`: web's only purchase path is that SDK, and Metro can resolve with no platform at all.
- **Moti costs ~250 KB (6 % of the bundle) for six entrance animations**, since it pulls framer-motion. It stays in the starter, where convenience wins; an app whose Moti is only entrances replaces it with a Reanimated-only transition view — `analyze` decides — and an app that removed it does not bring it back.

### Internationalization

20 languages: en, fr, es, de, pt-BR, zh-CN, zh-TW, ja, ko, ar, hi, bn, ru, id, tr, it, nl, sv, pl, vi (`i18n/service.ts`, `i18n/languages/`, lazy-loaded). RTL (`ar`) triggers `I18nManager.forceRTL` + restart.

**RTL mirrors the layout, never a transform.** React Native reverses a row and reads `left`/`right` as `start`/`end` in Arabic, but a `translateX` still moves right: something that slides along a row keeps its position logical and flips only its travel by `I18nManager.isRTL` (`SlidingSelector`), and a directional glyph is flipped by hand (`DirectionalIcon`).

**`common.*` is the shared UI vocabulary**, the one namespace allowed to hold a key with no current reader: deleting *Cancel* or *Retry* would bill the next app a translation session. Everywhere else, a key with no reader is dead and goes.

**Translation policy:**
- Code changes that touch i18n keys provide values in **EN and FR only**, the source of truth.
- The other 18 languages are translated in **dedicated sessions**, never alongside feature work.
- **A dedicated session brings every language to full parity with `en.json`** — key for key, and one value per plural category the locale has: six in `ar`, four in `ru` and `pl`, three in `fr`, `es`, `it` and `pt-BR`, one in `ja`, `ko`, `zh-*`, `id` and `vi`, two everywhere else (`Intl.PluralRules(locale).resolvedOptions().pluralCategories`). `fallbackLng: 'en'` renders a missing key or plural form in English rather than failing, so a partial pass ships half-translated screens nothing reports. A string that interpolates `count` is a plural: i18next looks up its suffixed forms before the bare key.
- Translations are contextually adapted, not literal: grammatically correct but mechanical is wrong.

**Voice:**
- **One register per language, the whole app, onboarding included.** Formal in **fr** (`vous`), **ru** (`вы`), **tr** (`siz`), **id** (`Anda`), **hi** (`आप`), **bn** (`আপনি`), **ar**, **zh-CN/zh-TW** (`您`), **ja** (です・ます), **ko**; informal in **es** (`tú`), **de** (`du`), **it** (`tu`), **nl** (`je`), **pl** (`Twój`), **pt-BR** (`você`), **sv**, **vi** (`bạn`). An app may flip a language, but its whole file at once — never half of it.
- No process boilerplate: no "successfully" / "avec succès" on a confirmation, no "Please" / "Veuillez" before a recovery action, no "Are you sure you want to…" / "Êtes-vous sûr de vouloir…" on a confirm dialog. Say what happened, or what the next tap does.
- Errors name the problem in the user's terms, never the transport's: `server error`, `rate limit`, `timeout`, `layout` do not reach the UI.
- EN labels are **sentence case** (`Select language`); proper nouns keep their capitals (Pro, Google Play, Privacy Policy, Terms of Service).
- The separator between two clauses on one line is `·`, and the ellipsis is `…`.

### Path Aliases

`apps/mobile/tsconfig.json`: `@/*`, `@components/*`, `@services/*`, `@stores/*`, `@hooks/*`, `@utils/*`, `@constants/*`, `@types/*`, `@i18n/*`, `@assets/*`. No `@providers/*` or `@contexts/*` alias — import as `@/providers/*`, `@/contexts/*`.

## Architecture (api)

Hono app at `apps/api/src/index.ts`: `GET /health` (unauthenticated), `GET /example`, `GET /example/premium` (`403 premium_required` for a free caller). Middleware on `/example/*`: `rateLimiter` (30 req/IP/60s) then `apiKeyAuth` (`x-api-key`). `Env` (`src/types.ts`): `API_KEY`, `FIREBASE_*`, `REVENUECAT_SECRET_API_KEY` (secret), `REVENUECAT_PROJECT_ID` (`[vars]`), `API_RATE_LIMITER`, `ENTITLEMENT_CACHE` (KV).

**The server decides who is premium; the app is never taken at its word.** `entitlementContext` (`middleware/premium.ts`) reads the RevenueCat app user id from `x-rc-customer-id`, resolves the tier once through `isPremiumCustomer` (REST API v2) and hands `isPremium` to the route, which decides what a free caller gets.
- **The id's format is checked, not its owner** (`CUSTOMER_ID_RE`): the API key ships in the APK, so anyone can send any id, and what protects a subscriber is that an anonymous id cannot be guessed.
- **Unknown is not "no."** A RevenueCat that does not answer is `503 entitlement_check_unavailable`: nothing refused for good.
- **Inert until configured.** Without `REVENUECAT_SECRET_API_KEY` and `REVENUECAT_PROJECT_ID` every caller is premium and the isolate logs it once, so a Worker deployed before RevenueCat refuses no subscriber. The app's `FORCE_PRO` never reaches it.
- **Answers are cached in `ENTITLEMENT_CACHE`**: a yes for up to 6 h and never past the entitlement's expiry, a no for 60 s. The binding has no id in `wrangler.toml`: the first deploy creates the namespace.

**One entitlement, or a filter.** v2 names an entitlement by its internal id, not by the lookup key the app reads, so any active entitlement counts as premium; an app that sells a second one filters `entitlement_id` in `resolvePremium`, or the check says yes for the wrong purchase. The grace period is the store's (Monetization): the server adds no window.

## Architecture (web)

Next.js 16 App Router, **a static export** (`output: 'export'`) into `apps/web/out/`. Two duties fall to the host: serving `/privacy` from `privacy.html` (Firebase Hosting needs `cleanUrls: true`; Cloudflare Pages, Netlify and Vercel do it) and sending the security headers, since an export ignores `headers()` — the README lists both. English sits at the root, where a crawler and a shipped link find it without a server redirect.

- **Every URL comes from `lib/routes.ts`** (header, footer, language link, hreflang, sitemap). The legal slugs are the same in every locale (`/fr/privacy`, never `/fr/confidentialite`).
- **Each locale is its own root layout**, because only a root layout renders `<html lang>`; `app/not-found.tsx` has no layout above it and renders its document itself.
- **Copy lives in typed dictionaries** (`content/{en,fr}/`), French checked against English's types. EN and FR only.
- **`lib/site.ts` holds the site's identity**, swept by `setup.sh`; the legal pages print a template notice while a bracketed placeholder or `example.com` remains.
- **The privacy policy describes what the starter does**, and changes in the same commit as a new SDK, a permission or data sent to a server. The site sets no cookie and loads no web font, analytics or third-party script — the policy says so, and adding any changes it.
- **No `aggregateRating` and no `offers` in the JSON-LD**: Google requires the first to reflect real reviews, and a price copied here drifts from the store's.
- **The site shares the mobile app's React, to the version.** `node-linker=hoisted` places one copy at the root and Metro resolves the mobile's React from there, so `react` and `react-dom` in `apps/web/package.json` pin the mobile's exact version and a bump moves both. Any package both apps resolve follows the rule — which is why the site is plain CSS with `light-dark()` tokens and no Tailwind v4 beside NativeWind's v3.
- The favicon and home-screen icon come from `scripts/generate-brand-assets.py` (Brand assets).

The Android release workflow installs the whole workspace, the site included, and builds nothing of it.

## Store policy

What costs a rejected release or a suspended account rather than a bug report. Most of it sits beside the code it constrains: the review card never pre-filtered (App Rating); no social proof the store cannot back, and the charge stated beside every buy button (Monetization); no ad request before consent or on a Test Lab device (Monetization, `ADS.md`); a permission declared only where something uses it (Build & Release); no `aggregateRating` on the site (Architecture (web)). Two rules have no code to sit beside:

- **No urgency the store does not enforce.** A countdown, a "today only" or a "last chance" over a price that does not change is false scarcity — misleading under Play's policies, banned outright by the EU's Unfair Commercial Practices Directive. Urgency is allowed only when a real store offer ends, and it states that date.
- **A declaration is a form, not a design constraint.** Where Play restricts a permission to certain kinds of app, eligibility is a product decision taken once; the declaration is filed at submission — never narrow a feature or drop an API because "Play requires a declaration". What binds is what it affirms: an in-app disclosure in plain words before the system dialog, never after, and a configuration no wider than the need.

## Testing

**No tests.** Do not write, suggest, or run tests. Do not add test files or testing libraries.

## Code Style

- **Self-documenting code, and zero comments by default.** A new type, constant, function or block gets no comment; a design choice, a naming rationale or a narration of why the code works is not reason enough, even when true and not obvious. A comment is kept for what the code cannot say — a crash or OOM history, a security boundary, a store or legal constraint (Play, GDPR/UMP), a platform or library trap (React Native, NativeWind, Reanimated) that breaks silently once "simplified" away — and it names the constraint and what breaks without it. Never a what-comment, a task-trace comment, one restating the line below, or one repeating an explanation that lives at the definition being called.
- **Three layers, one responsibility each.** `services/` holds logic — storage, SDKs, pure policies — with no React, no `router` and no `t()`; `hooks/` holds React orchestration; `app/` and `components/` hold assembly and JSX. `reviewPolicy.ts` and `contextualPaywall/policy.ts` are the shape: a pure decision handed its state. A screen file past ~250 lines usually means logic settled into it — lift it into a hook, and the React-free part into a service. The one service that calls `t()` is `channels.ts`: Android draws a channel's name in its own settings, where no screen can hand it over.
- TypeScript strict (`strictNullChecks`, `noImplicitAny`). Functional components with hooks.
- **Functions with 2+ parameters use a single object parameter** — `fetchData({ id, signal })`, not `fetchData(id, signal)`.
- **Atomic Zustand selectors** — `useStore((s) => s.field)`, never object selectors.
- **A memo keys on content, never on the identity of an array its callers build**: a hook that takes an array passed as a literal keys its `useMemo` on `codes.join('|')`, not on `codes`, and its default is a module constant (`const NO_CODES: readonly string[] = []`), never `= []` inline — a fresh default in an effect's dependencies re-runs it every render.
- Environment variables: `apps/mobile/.env` (see `.env.example`), `apps/api/.dev.vars` (see `.dev.vars.example`).
